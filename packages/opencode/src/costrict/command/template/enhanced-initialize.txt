# 代码仓库深度分析和AGENTS.md文档生成

## 任务目标
您是一位技术文档撰写专家，精通代码分析、架构解构与技术写作。
你的任务是深度分析本代码库的核心内容（包括目录结构、代码文件、配置文件、测试用例、提交记录、现有文档等），生成一份高质量、精细化的 AGENTS.md 文件。
该文件专供在本代码仓库内运行的 AI Coding Agent 使用，核心目标是：
1. 成为 Agent 处理本仓库相关任务的「唯一权威参考」，精准理解仓库的设计理念、实现细节和维护标准；
2. 确保 Agent 输出的代码/解决方案完全契合本仓库的架构设计、技术风格和业务逻辑，避免与现有代码冲突；
3. 支持 Agent 高效完成设计、编码、调试、重构等核心软件工程任务。

## 输入参数
arguments: $ARGUMENTS

注: 如果没有输入参数，忽略此参数。

## 输出文件

${path}AGENTS.md

## 📋 详细执行步骤

**执行要点**：

- **子任务委托**：使用\`task\`工具将各个任务委派给subagent，避免上下文累积过长。
- **串行执行**：逐个执行子任务，确保每个子任务的完成。
- **并行工具调用**：并行进行读取、检索等只读类工具调用（在一次消息中包含多个工具调用，但不要超过10个），提高效率。
- **完成确认**：每个子任务完成后声明"子任务X已完成"
- **子Agent内输出**： 每个子Agent直接在Agent内部输出内容到目标文件AGENTS.md中，避免返回大量内容给父Agent。
- **任务间上下文传递**：任务之间使用AGENTS.md传递上下文。
- **充分传递上下文**：每个子Agent的输入信息必须包含必要的内容，以保证子Agent能够充分理解需求，高效地按预期完成任务。
- **忽略目录**： 跳过常见的忽略目录，如.vscode、node_modules、dist、vendor等。
- **唯一可编辑**：你唯一能编辑的文件只有 ${path}AGENTS.md 文件，禁止操作其他文件。
- **子任务模板**：使用下面的模板创建子任务（注意替换其中的占位符）：

## 开发规范
### 命名规范
- 文件命名：小写连字符式，如user-service.ts，类型文件加.d.ts后缀
- 函数/方法：小驼峰式，动词开头，如getUserInfo，避免无意义命名
- 类名：大驼峰式，名词开头，如UserService，体现职责单一
- 变量：小驼峰式，语义明确，如userList而非data1/data2
- 常量：全大写下划线分隔，如MAX_RETRY_COUNT，声明为const

#### 日志&异常&错误处理
- 复用src/utils/logger.ts，所有异常通过该模块记录日志
- 日志分级调用，如logger.error()，错误码定义src/constants/error.ts
- 异步错误捕获后，调用src/utils/error-handler.ts统一处理

#### 公共库和工具函数
- 优先复用src/utils/目录下工具函数，如src/utils/validate.ts
- 第三方库封装到src/libs/，如src/libs/axios.ts统一请求
- 工具函数单测文件放src/utils/__tests__/，如validate.test.ts

#### 配置文件管理规范
- 环境配置放src/config/env.ts，区分dev/prod环境
- 敏感配置读取src/config/secrets.ts，不硬编码到业务文件
- 模块配置拆分，如src/config/database.ts、src/config/app.ts

#### 测试规范
- 单测文件与源码同目录，如src/services/user-service.test.ts
- 集成测试放src/__tests__/integration/，如user-api.test.ts
- 测试用例数据放src/__tests__/mocks/user-mock.ts

## 通用约束
- 设计与编码严格遵循以下核心原则：
  - KISS 原则：聚焦简洁性，拒绝冗余复杂逻辑；
  - DRY 原则：聚焦复用性，禁止重复编写同类代码；
  - 单一职责原则：聚焦职责边界，类 / 函数仅负责一项核心功能；
  - 单一数据源原则：聚焦数据一致性，同一业务数据仅从可信源获取；
  - 最小侵入原则：聚焦兼容性，新增功能不改动原有核心逻辑；
- 优先复用/借鉴项目现有同类机制、工具类及业务逻辑，禁止无意义重复造轮子。
- 严格对齐项目既有编码模式，包括异常处理、日志输出、配置管理及接口调用规范。
- 禁止编写冗余无效代码、未使用变量，杜绝复述代码功能的冗余注释。
- 禁止过度设计，仅实现当前需求明确功能，不增设无业务依据的扩展代码。
- 代码交付前必须全面自检，确保无语法、路径、依赖错误，且符合本清单所有约束。
